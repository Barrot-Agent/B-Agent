# Grok Swarm — Scale With Multiple Agents

**Premise.** One agent is a worker. Several agents with handoffs are a team — and a new class of failure.

## Beats

1. Documented: multiple Bots can work together like a team; one Bot's routine produces, another drafts, a third reviews, then the bundle comes to you for approval.
2. Documented: a multi-agent model exists on the API (`grok-4.20-multi-agent-0309`), priced like the 4.20 text models.
3. Topologies that work: pipeline (produce → review → approve), fan-out (research N sources), specialist pool (route by task type).
4. Topologies that don't: unbounded debate, agents voting on facts, recursive delegation with no budget.
5. Handoff contract: artifact + schema + confidence + open questions. Prose handoffs lose information.
6. The primary-Bot pattern: one agent answers 'what is everyone doing' so you are not polling five chats.

## What to measure

- Every extra hop multiplies cost and latency; measure both per topology.

## Do not

- Do not call it a swarm if there is no handoff artifact. Parallel prompts are not a swarm.
