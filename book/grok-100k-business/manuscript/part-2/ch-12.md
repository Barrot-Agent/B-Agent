# Memory, Governance, and Approvals — The Fence Around Autonomy

**Premise.** The fence is the product. Without it, autonomy is a liability with a demo.

## Beats

1. Four rules written before the first run: may-do-alone, must-ask, may-never, what-happens-when-wrong.
2. Memory schema: durable facts vs run state; one file per agent; an explicit expiry for anything price-like.
3. Approval design: the gate must cost seconds, or the operator will route around it.
4. Budgets: per-run token ceiling, per-day spend ceiling, and a hard stop that is enforced in code, not in a prompt.
5. Rollback: every write is a diff or a note; deletions are two-phase; credentials are never in the agent's reach.
6. The ledger: hash-chained action records so history cannot be silently edited.

## What to measure

- A governance check that fails the build on unsupported claims is worth more than a policy document.

## Do not

- Do not describe approvals as a UI feature. Describe what is technically impossible for the agent to do.
