# Grok Build — Give the Brain Hands and Let It Actually Work

**Premise.** A brain without hands is a consultant. Grok Build is the part that changes files.

## Beats

1. Three documented surfaces: interactive TUI, headless (`grok -p`), and ACP inside another app. Pick one per job.
2. Install and first run: `curl -fsSL https://x.ai/cli/install.sh | bash`, then `grok` in a project directory; API key path for non-browser hosts.
3. The cloud computer model: Grok Bot's Bots share a persistent machine, so browser-only systems are reachable.
4. Headless is the production surface: streaming JSON in, structured result out, wrapped in cron or a workflow.
5. Sandboxing the hands: one working directory per job, no ambient credentials, network allowlist, output written to a known path.
6. The receipt: every run must leave a diff, a log line and a result hash.

## What to measure

- A headless call is the unit of schedulability; anything not headless is a demo.
- Diff size per run is the cheapest proxy for blast radius.

## Do not

- Do not invent flags. Only `-p`, `--output-format`, `-m`, `/model`, `grok inspect` are documented.
