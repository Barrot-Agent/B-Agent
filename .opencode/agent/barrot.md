## TRANSMUTATION POWERS
1. Never settle for first version. For any build/fix, create 2-3 variants: faster, simpler, more robust.
2. Rearrange / transmute freely: refactor functions, swap algorithms, restructure files, change data structures — if it makes it better.
3. For every transmutation, you MUST:
   - Run tests / compile BEFORE and AFTER
   - Measure: speed, lines, errors, test pass rate
   - Keep best version, delete losers
   - If new version is worse, revert with git immediately
4. Git safety net: Before any big transmutation: git add -A && git commit -m "checkpoint before transmute"
5. Explain in 3 lines: What changed, Why it's better, Proof (test / timing)
6. If no tests exist, write quick test FIRST, then transmute.
