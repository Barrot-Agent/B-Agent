**2. Meaningful executable branches / error paths**

| Location | Branch condition | Behaviour / error |
|----------|------------------|-------------------|
| `call_gradio` – header creation | `if HF_TOKEN:` | Adds `Authorization` header; otherwise no auth header. |
| POST response handling | `event_id = submit_resp.get("event_id")`  → `if not event_id:` | Raises `RuntimeError("No event_id …")` when the JSON response lacks `event_id`. |
| SSE loop – line parsing | `if line.startswith("event:")` | Updates `current_event`. |
| SSE loop – data line detection | `if not line.startswith("data:"):` | Skips non‑data lines. |
| SSE loop – payload filtering | `if payload in ("", "[DONE]", "null"):` | Ignores empty/terminal markers. |
| SSE loop – JSON decode | `try: parsed = json.loads(payload) except JSONDecodeError:` | Silently continues on malformed JSON. |
| SSE loop – event‑type handling | `if current_event == "generating": … elif current_event == "complete": …` | Prints a preview message vs. captures the final payload (`last_data = parsed; break`). |
| After SSE loop | `if not last_data:` | Raises `RuntimeError("No 'complete' event …")` when a final event never arrived. |
| `main` – token warning | `if not HF_TOKEN:` | Emits a warning on stdout. |
| `main` – download flow | (no explicit branch – but network I/O may raise; not a code branch). |
| `ModelManager.__init__` | `config or ModelConfig()` – always creates a config object. |
| `ModelManager.is_loaded` | Returns `self._model is not None`. |
| `ModelManager.get_metadata` | Returns a **copy** of the constant dict (no branch). |
| `ModelManager.load` – import block | `except ImportError as exc:` → logs & re‑raises. |
| `ModelManager.load` – config‑driven kwargs | `if self.config.load_in_8bit:` → adds `load_in_8bit`; `elif self.config.load_in_4bit:` → adds `load_in_4bit`; `elif self.config.tensor_type == "bf16":` → adds `torch_dtype`. |
| `ModelManager.load` – device mapping | `if self.config.device != "auto":` → explicit device map; else `"auto"`. |
| `ModelManager.load` – generic exception | `except Exception as exc:` → logs error & re‑raises. |
| `ModelManager.unload` – conditional deletions | `if self._model is not None:` / `if self._processor is not None:` → delete and set to `None`. |

These are the **only** logical forks that a unit test can force or observe.

**5. Dependencies that need to be mocked**

| Dependency | Why it must be mocked | Typical mock approach |
|------------|----------------------|-----------------------|
| `urllib.request.urlopen` (both POST and SSE GET) | Performs real HTTP requests; SSE stream is an iterator of bytes. | `mock.patch("urllib.request.urlopen")` returning a context‑manager mock whose `__enter__` yields an object with `.read()`/`.__iter__()` as needed. |
| `json.load` (used on the POST response) | To feed a controlled dict without network I/O. | Provide a mock file‑like object whose `read` returns a JSON string, or simply set `mock_urlopen.return_value.__enter__.return_value = io.BytesIO(b'{"event_id":"123"}')` and let `json.load` work naturally. |
| `os.makedirs`, `time.strftime`, `open`, `os.path.join` | `main()` writes a file; we don’t want to touch the real filesystem. | Patch `os.makedirs` (no‑op), `open` with `mock.mock_open()`, and `time.strftime` to a deterministic value. |
| `torch`, `transformers.AutoModelForVision2Seq`, `transformers.AutoProcessor` | Heavy external libraries; we only need to verify they are called with the correct arguments. | Insert lightweight dummy modules into `sys.modules` (e.g. a simple `class Dummy: pass`) and set `from_pretrained` to a `Mock`. |
| `barrot_agent.logger.get_logger` (indirect) | Logging side‑effects are irrelevant for logic. | Patch `barrot_agent.logger.get_logger` to return a `Mock` with `info`, `error` methods that do nothing. |
| Environment variables (`HF_TOKEN`, `IMAGE_PROMPT`) | Test different auth / prompt paths. | Use `monkeypatch.setenv` or temporarily modify `os.environ`. |

All mocks are straightforward and do **not** alter the production code.

**6. Implementation defects that the source directly reveals**

| Defect / questionable behaviour | Evidence in code | Potential impact |
|--------------------------------|------------------|------------------|
| **Missing handling of non‑200 HTTP responses** – `urllib.request.urlopen` will raise `URLError`/`HTTPError`, which bubbles out as an uncaught exception. The function does not translate this into a user‑friendly error. | No `try/except` around the two `urlopen` calls. | A network failure crashes the CLI rather than returning a clear message. |
| **`HF_TOKEN` empty string is treated as “no token” for the POST request but *is* sent as an empty Authorization header for the SSE poll** (`headers={"Authorization": headers.get("Authorization", "")}`) – the header key will be present with an empty value, which some servers reject. | The conditional for the GET request only checks `if HF_TOKEN` (truthy), not `if headers.get("Authorization")`. | Might cause 401 errors when the environment variable is defined but empty. |
| **`load()`’s device‑map logic** – When `self.config.device != "auto"` the code sets `load_kwargs["device_map"] = self.config.device`. The `device_map` argument expects a *mapping* (e.g. `{"": "cpu"}`) or the string `"auto"`; passing a plain device string (e.g. `"cpu"`) is not a documented usage for `from_pretrained`. | Direct assignment without validation. | Could raise a runtime error for certain device values. |
| **`ModelManager.unload()` does not reset the logger state** – It logs “Model unloaded.” even if the manager never loaded a model. This is benign but noisy. | No guard around the log statement. | Minor – just extra log noise. |
| **`call_gradio` silently discards malformed SSE payloads** – The `except JSONDecodeError: continue` swallows any JSON error, making debugging of server‑side issues harder. | Explicit `continue` on `JSONDecodeError`. | Users may get a “No complete event” error without knowing the payload was actually received but malformed. |
| **`call_gradio` does not enforce a maximum number of SSE iterations** – If the server never sends a `complete` event, the loop could run indefinitely until the request times‑out (180 s). While a timeout exists, a more graceful early‑exit (e.g., max retries) would be nicer. | Loop runs until break or request timeout. | Potentially long‑running hangs. |
