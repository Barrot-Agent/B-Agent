**2.  Meaningful executable branches / error‑paths**

| Location (line‑concept) | Condition / branch | Effect on control‑flow / stats |
|--------------------------|--------------------|--------------------------------|
| **Score threshold** | `if score_val < self._cfg.min_score:` | → records a rejection, increments `stats["rejected"]`, **continues** to next component |
| **Ping‑pong outcome** | `if exchange.final_phase != Phase.ACCEPTANCE:` | → records a rejection, increments `stats["rejected"]`, **continues** |
| **Dry‑run guard** | `if not self._cfg.dry_run:` (sandbox block) | – when `dry_run=True` sandbox is *skipped* (no sandbox stats). |
| **Sandbox result** (inside dry‑run‑off block) | `if not sb_report.passed:` | → records a rejection, increments `stats["rejected"]`, **continues** |
| **Human‑approval decision** | `if not decision.approved:` | → records a rejection, increments `stats["rejected"]`, **continues** |
| **Successful acceptance path** | All above checks passed | → increments `stats["accepted"]` (and later, after the part of the file that was cut off, presumably `stats["promoted"]`). |
| **Stat counters** | Various `stats["…"] += 1` lines | Each branch updates a different counter – exercising each branch proves the counter logic. |
| **Provenance recording** | Calls to `self._provenance.record_*` – they are side‑effects but do not change control flow; they are still useful to assert that they are called with the right arguments. |

There are **no explicit exception‑raising paths** in this file, but failures in the *mocked* dependencies (e.g. `discover_all` returning an empty dict) exercise the “no‑components” path (the `for component_score in ranked:` loop is never entered).

**6.  Implementation defects that are *directly* visible from the source**

| Defect | Location / description | Why it matters (test will expose) |
|--------|------------------------|-----------------------------------|
| **`stats["promoted"]` never updated** | The visible code never touches `stats["promoted"]`. The downstream part of the file (cut‑off) likely should increment it after a successful registry promotion, but that line is missing. | A test exercising the full successful path (dry‑run **or** real run) will see `stats["promoted"]` remain `0` even though the component was “integrated”. This is a logical bug – the counter does not reflect reality. |
| **Potential `adapter` `None` handling** | The code builds `adapter = build_adapter(inv)` and later accesses `adapter.__class__.__name__` **only if `adapter` is truthy**; otherwise it falls back to `"NoAdapter"`. If `build_adapter` returns an object that is falsy but still has a `__class__` (e.g. an object that implements `__bool__` returning `False`), the fallback would be wrong. | Not a failing test today, but a hidden contract – the test can deliberately make `build_adapter` return a custom object with `__bool__` = `False` to see that the code mis‑labels it. |
| **Missing handling of empty `ranked` list** | If `MCPScorer.rank` returns an empty list (e.g. all components filtered out before ranking), the `for component_score in ranked:` loop is skipped, and only `stats["discovered"]` is non‑zero. This is *not* an error, but the function returns without ever calling provenance for “no‑integration” events. If the business logic expects a “no‑action” provenance entry, it is absent. | A test where `ranked` is empty (e.g. mock `rank` → `[]`) will confirm that the pipeline finishes cleanly without raising and that `stats` reflects zero proposals, accepted, etc. |
| **`self._cfg.dry_run` guard does not affect provenance “sandbox” status** | The provenance call later (outside the snippet) records `test_results={"sandbox": "passed" if not self._cfg.dry_run else "skipped"}` – that part is correct, but the earlier *sandbox* block only runs when `dry_run=False`. If a user mistakenly sets `dry_run=False` but the sandbox returns `passed=False`, the code will still record a rejection *and* later record a “sandbox”: “passed” in provenance (since the guard is only on the `if not self._cfg.dry_run`). The snippet we have does not show the provenance call, but the logic suggests a possible inconsistency. | A test that sets `dry_run=False` and forces `sandbox.passed=False` will see `stats["rejected"]` incremented, yet the provenance record (once the later code runs) would claim `"sandbox": "passed"` – a mismatch. |
| **No explicit handling of unknown `Phase` values** | The code assumes `exchange.final_phase` is a `Phase` enum with a `.value` attribute. If a buggy `MCPPingPong` implementation returns something else (e.g. `None`), the string interpolation will raise `AttributeError`. | A defensive test could mock `run` to return an object lacking `.final_phase` to see that the pipeline crashes – indicating missing validation. |

These defects are **detectable** with the pytest matrix described above (especially #1 and #4). Adding assertions for the missing `promoted` counter will surface #1 immediately.
