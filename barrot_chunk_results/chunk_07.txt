| **EvidenceQualityEngine._recency_score** | `if not value` | Returns `0.5` for missing/falsey timestamp. |
| | `try … except (TypeError, ValueError)` | Returns `0.5` on parsing failure. |
| | `if age_days <= 30` → `1.0` |
| | `elif age_days <= 180` → `0.8` |
| | `elif age_days <= 365` → `0.6` |
| | `else` → `0.4` | Four age‑based buckets. |
| **EvolutionEngine.ingest** | `if any(item["id"] == digest for item in corpus)` | Duplicate detection – returns `"duplicate"`. |
| | `confidence = max(0.0, min(1.0, confidence))` | Clamps confidence (three logical paths: <0, >1, in‑range). |

| **EvolutionEngine.improvement_targets** | `domains = {item.get("domain") for item in corpus}` – may contain `None` if a record lacks `domain`. |
| | List‑comprehension filter `if domain not in domains` | Generates 0‑N target dicts based on missing domains. |
| **Filesystem I/O** (both `load_corpus` and `ingest`) | `if not CORPUS_FILE.exists()` | Returns empty list vs. reading JSON. |
| | `json.loads(...)` and `json.dumps(...)` – can raise if the file is corrupted (not caught, bubbles up). |

**6. Implementation defects that the source itself reveals (and that tests will surface)**  

| Defect / edge case | Explanation | Test that would catch it |
|--------------------|-------------|--------------------------|
| **`_recency_score` treats any truthy but non‑ISO value as “parse error” → returns 0.5** – this is intentional, but the fallback value (0.5) is the same as the “no timestamp” case, making it impossible to distinguish between “missing” and “malformed”. If the spec expected a different penalty, the current implementation is a bug. | A test feeding `"2023-13-01"` (invalid month) expects a distinct value (e.g., 0.3) – it will fail, revealing the design issue. |
| **`Improvement_targets` includes `None` in the domain set when an item lacks a `domain` key**, potentially causing *every* priority to be reported even though the corpus already has a record (albeit malformed). | Test `test_improvement_targets_none_present` (corpus item without `domain`). The current code will **still** emit all priorities – this is arguably a defect in the domain‑extraction logic. |
| **`ingest` writes the entire corpus even if the JSON file is corrupted** – `load_corpus` will raise a `json.JSONDecodeError`, bubbling up and aborting the whole engine. The engine has no graceful recovery. | A test that writes malformed JSON into the temp file, then calls `engine.ingest(...)` expects a clean exception; the failure demonstrates the missing error handling. |
| **`ingest` uses `any(item["id"] == digest …)` without guarding against missing `id` keys**. If an external process manually edits the corpus and removes an `id`, a `KeyError` will be raised. | Craft a corrupted corpus entry missing `"id"` and call `ingest`; the test will raise `KeyError`, exposing the assumption that the file is always well‑formed. |
| **`synthesize` treats missing `domain` as `"general"` – this is fine, but the return type’s `domains` mapping will contain `"general"` even when *all* items lack a domain.** If the caller expects only real domains, this could be misleading. | A test where every corpus item omits `domain`; assert that `"general"` appears exactly once per item. If the spec says it should be omitted, the test flags the behavior. |

These defects are **directly observable** with the pytest cases outlined above; they will either be caught as failing assertions (if the test encodes the intended contract) or will surface as unexpected exceptions, prompting a design discussion.
