# Production workflow

Ten stages. Eight roles. Fail-closed at every stage. A stage is complete only
when its artifact exists and its gate has evidence.

## 1. The ten stages

| # | Stage | Owner | Output | Gate |
|---|---|---|---|---|
| 1 | Opportunity | Market Intelligence + Product Strategy | Product row in `PRODUCTS_MATRIX.md` | Template 1 only; Templates 2-6 locked |
| 2 | Research | Research | `research/SOURCES.md`, `MARKET_RESEARCH.md`, `EVIDENCE_LOG.md` | Every claim has a source or is marked UNKNOWN |
| 3 | Feasibility | Product Strategy + Technical Development | Scope, effort gate, cost model | Buildable with existing tools in one iteration |
| 4 | Capability Check | Technical Development + Independent Verification | `CAPABILITY_LEDGER.md` | All ten components PROPOSED, none Active |
| 5 | Spec | Product Strategy | `PRODUCT_SPECIFICATION.md` | Every requirement testable |
| 6 | Production | Content/Production + Technical Development | Deliverables, docs, 76 tests | Full suite green, examples generated by code |
| 7 | Independent Verification | Independent Verification | Verification report | Not the builder; re-runs tests and audits claims |
| 8 | Packaging | Business Operations + Content/Production | Tier manifests, package contents | Manifest matches files; no internal docs in buyer package |
| 9 | Commercial Prep | Business Operations | `SALES_COPY.md`, `PRICING.md`, `marketing/` | No claim without evidence; no publish |
| 10 | Human Authorization | Sean | Written approval | Explicit sign-off for publish, price, or transaction |

## 2. The eight roles

| Role | Owns | Must not do |
|---|---|---|
| Research | Sources, quotes, retrieval dates | Present a vendor claim as measured fact |
| Market Intelligence | Demand, competition, platform status | Inflate a sample into a market size |
| Product Strategy | Scope, tiers, kill criteria, pricing rationale | Add a feature outside the template |
| Content/Production | Buyer-facing docs, templates, sales copy | Add a claim not in the evidence log |
| Technical Development | Kit code, CLI, examples, tests | Mark a component Active without proof |
| QA | Test execution, negative controls, regression log | Accept "it works" without a command and output |
| Business Operations | Packaging, delivery, refunds, invoices | Publish or charge without sign-off |
| Independent Verification | Re-run tests, audit claims, check governance | Fix the thing it is verifying |

**Separation rule.** The builder cannot sign off Stage 7. If the same agent
built the artifact, a different agent or a human must verify it. In this run the
builder produced the artifact, so Stage 7 requires a separate verifier; see
section 5.

## 4. Fail-closed rules

These are hard. A violation stops the run; it does not get a workaround.

1. Never merge to `main`. Work stays on a `phase1/...` branch or PR.
2. Never publish a listing, price, or file to a store.
3. Never change a live price.
4. Never run a financial transaction, refund, or payout.
5. Never claim a component is Active without a HEAD pin and a test log.
6. Never describe a stated bounty as escrow.
7. Never promise a merge, a payment, or income.
8. Never delete a failing test to make the suite green.
9. Never include a secret, token, or buyer datum in the package.
10. Never build Templates 2-6 in Phase 1.

## 5. Independent verification

The verifier receives only: this directory, the test command, and the governance
rules. It must:

- run `python3 -m unittest discover -s tests` from `deliverables/` and report
  the exact count;
- run `./run_selftest.sh` and compare;
- try to break the validator with a body that contains a banned claim;
- check that every numeric claim in `SALES_COPY.md` appears in
  `research/EVIDENCE_LOG.md` or `research/market_measurement.json`;
- check that all ten components are still PROPOSED;
- confirm no merge or publish happened.

It must not edit files. Its report goes to
`evaluation/INDEPENDENT_VERIFICATION.md` and is signed with the verifier's
identity. An unsigned or self-signed report is not verification.

## 6. Kill criteria

| Rule | How to detect | Action |
|---|---|---|
| No evidence of demand | Research finds no live paid-issue inventory or no plausible buyer | Kill before production |
| Cost > 3x price | Fee + infrastructure + support exceeds 3x price | Kill or reprice |
| Capability not buildable in one iteration | Requires an external dependency, credential, or platform not already present | Kill or defer to a later phase |
| Governance violation | Publish, merge, price change, transaction, secret, or unproven Active claim | Stop, revert, log |

## 7. Rollback

- Code: `git revert <commit>` on the branch. The product is additive; nothing
  outside `products/github-pr-template-pack-self-guided/` imports it.
- Docs: delete the directory. No other product references it.
- Publish (if ever approved): unpublish the listing, keep buyer access, issue
  refunds under the 14-day policy, and log the reason.
- Price (if ever approved): restore the previous price and add a changelog line.
  Existing buyers keep the terms they bought.

## 8. Handoff

The run stops at Stage 10. The human receives:

- branch name and HEAD SHA;
- file list and test log;
- unresolved items: independent verification, legal review, live checkout test,
  real buyer test;
- one decision: authorize publication or reject.

No further building happens until that decision is written.
